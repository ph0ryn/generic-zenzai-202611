# AJIMEE評価

[学習](../README.md#usage)とは別コマンドで実行する。評価に失敗しても学習のやり直しは不要。
学習コマンドは完了時に、実行ディレクトリの`model-path.txt`へモデルパスを自動で書き出す。
学習と同じColabランタイム・ディレクトリで、次のセルを実行する。
日時入りパスの手入力や、一時変数への格納は不要。

```python
!uv run --locked generic-zenzai-evaluate --model "$(cat model-path.txt)"
```

ローカルのシェルでは、先頭の`!`を除いて実行する。
学習が正常に完了してから評価する。次の学習開始時には以前のモデルパスを空にし、
完了したときだけ新しいパスを書き出す。

別のモデルを評価するときは、従来どおり`--model /path/to/model`で直接指定できる。
保存済みモデルとtokenizerだけを読み、評価中のダウンロードは行わない。
CUDA GPUを使わない場合は`--cpu`を付ける。ローカルでも同じCLIを使える。

## 評価データと条件

[AJIMEE-Bench](https://github.com/azooKey/AJIMEE-Bench)の`JWTD_v2/v1`を使う。
このrepoが参照するデータは200件（文脈あり100件・なし100件）。
データはコピーせず、[submodule](<../benchmarks/AJIMEE-Bench>)のcommitで固定する。
既存cloneでの未初期化時や、このrepoの更新後は次を実行する。`--remote`は付けない。

```python
!git submodule update --init
```

別のcheckoutを使う場合は`--benchmark /path/to/AJIMEE-Bench`を指定する。
そのcheckoutのHEADを使い、実際のcommitとデータのSHA-256を結果に記録する。
未初期化や、評価データがHEADの内容と異なる場合はエラーになる。

- 学習と同じプロンプトで、左文脈は末尾40文字まで。読みは分割せず全文を入力する。
- 1件ずつ、fp32・greedy（サンプリングなし、beam数1）で生成する。
- 生成はEOSで終了し、上限は64トークン（`--max-new-tokens`で変更）。
  EOSで終了しなかった件数も集計する。
- 入力＋生成上限が512トークンまたはモデルの位置上限を超える場合は停止する。
  データの除外や読みの切り詰めは行わない。必要なら生成上限を下げて再実行する。

これは**モデル単体のかな漢字変換評価**であり、Zenzaiの辞書・探索・読み制約・量子化を
含むIME全体の評価や、実機での速度評価ではない。
モデル間の比較では、評価データ・文脈条件・生成上限を揃える。

## 指標と結果

実行中は各項目の判定とMinCERだけを1行で表示する。読み・文脈・予測・許容解はログに出さない。

```text
1/200 | 判定: 完全一致 | MinCER: 0.0000
2/200 | 判定: 不一致 | MinCER: 0.5000
```

最後に「実験サマリー」を表示する。この部分をコピーすれば、Driveを開かずに
学習条件・学習指標・評価条件・結果をまとめて共有できる。

- 学習: 元モデル、データ件数、周回数、更新回数、学習率、バッチ、計算精度、時間、loss、トークン正解率。
- 評価: 件数、文脈長、生成上限、生成設定、計算精度と実行環境。
- 結果: 全体・文脈あり・文脈なしの完全一致率と正解数、平均MinCER、生成上限到達件数。
  空出力の件数と平均生成トークン数も表示する。

学習中のトークン正解率は、文章全体の完全一致率とは異なる。
文脈あり・なしの100件は別の問題群なので、その差だけでは文脈の効果を判断できない。
個別の誤変換を調べる場合は、Driveの`predictions.jsonl`を確認する。

- **完全一致率**: 予測が許容解のいずれかと一致した割合。高いほど良い。
- **平均MinCER**: 各項目で、許容解ごとの「文字編集距離 ÷ 許容解の文字数」の最小値を取り、
  全項目で単純平均する。低いほど良く、0は完全一致。余分な生成により1を超えることもある。

生成の特殊トークンのみ除去し、空白除去や表記の正規化は行わない。
結果は既定でモデルの隣の`ajimee/eval-日時/`へ保存する。上のColab例ではDrive上になる。
`--output`で保存先の親ディレクトリを変更でき、実行ごとに新しいディレクトリを作る。

- `scores.json`: 区分ごとの件数・完全一致率・平均MinCER・EOS未終了件数。
  **全件成功時だけ保存され、評価完了の目印になる。**
- `predictions.jsonl`: 各項目の読み・文脈・許容解・予測・採点など。1件ごとに保存する。
- `evaluation.json`: モデルのパス、ベンチのcommitとハッシュ、プロンプト・生成条件・実行環境、評価時点の学習記録。
- `summary.md`: 画面に表示した実験サマリーと同じ内容。

中断時も保存済みの途中結果は残るが、評価の再開機能はない。
同じコマンドで全件を新しいディレクトリへ再評価する。

## 保存済み結果からサマリーを出す

評価時に表示された`eval-日時`のディレクトリを指定する。GPUや再推論は不要。

```python
!uv run --locked generic-zenzai-summary "/path/to/ajimee/eval-実際の日時"
```

`evaluation.json`・`scores.json`・`predictions.jsonl`を読み、サマリーを表示して
同じディレクトリの`summary.md`を作成・更新する。未完了の評価は集計しない。
新しい評価には学習記録も保存するため、元のモデルがなくても再出力できる。

この機能の追加前の評価では、記録されたモデルパスの隣にある`run.json`と
`train_results.json`から学習条件を読む。記録がなければ「不明」「未記録」と表示する。
古い学習結果にない更新回数・計算精度などは推測しない。
チェックポイントを評価した場合、周回数と更新回数はそのチェックポイントから読む。
