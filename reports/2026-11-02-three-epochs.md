# LLM-jp-150M 3周学習とAJIMEE評価

実施日: 2026年11月2日

[初回の1周学習](2026-11-02-first-training.md)を受け、
同じ5,000件を3周学習して比較した。
完全一致は200件中3件から11件に増え、平均MinCERは0.6848から0.5889に下がった。
生成を止めるだけでなく、変換内容にも改善が見られた。
ただし、読みから外れる誤変換や反復生成は残っている。

## 実験条件

| 項目 | 条件 |
| --- | --- |
| モデル | LLM-jp-3-150m |
| 学習方式 | 学習前モデルから全パラメータを追加学習 |
| 学習データ | 前回と同じ5,000件。文脈あり・なし各2,500件 |
| 入力 | 直前40文字までの文脈と、カタカナの読み |
| 学習対象 | 正解の変換結果と終了記号。入力部分には損失を付けない |
| 周回数 | 3 epochs、471更新。延べ15,000件 |
| バッチ | 2件 × 勾配累積16回。実効32件 |
| 学習率 | 5e-5。最初の5%で増やし、その後は線形に減衰 |
| 長さ上限 | 入力と正解を合わせて512トークン |
| 実行環境 | Google Colab / CUDA |
| 評価 | AJIMEEの200件。文脈あり・なし各100件 |
| 生成条件 | fp32、greedy、生成上限128トークン |

今回は合計3周の学習であり、1周学習済みモデルにさらに3周を追加したものではない。
保存記録では、モデル・学習データ・学習率・バッチなどの主要な設定が前回と一致した。
学習率の最大値と減衰方式は同じだが、周回数が増えるため減衰に使う更新回数も増える。

評価では同じ200件を使い、入力・文脈・許容解・プロンプト・生成条件の一致を確認した。
保存済みの予測を再採点し、集計結果と一致することを確認した。

## 学習の実行結果

学習とモデルの保存は完了した。
記録された学習時間は972.4秒、約16分12秒だった。
この時間には環境構築やモデル取得を含めない。

| 学習ログの指標 | 1周 | 3周 |
| --- | ---: | ---: |
| 更新回数 | 157 | 471 |
| 学習時間 | 363.0秒 | 972.4秒 |
| 学習全体の平均loss | 2.8823 | 1.3479 |
| 完了時のトークン正解率 | 60.09% | 96.33% |

学習データ上の予測誤差は下がり、完了時のトークン正解率も上がった。
ただし、この正解率は正解文のそれまでの部分を与えて次のトークンを当てる指標であり、
文章全体を自力で生成する評価時の完全一致率とは異なる。
96.33%とAJIMEEの5.50%を直接比較して、過学習と断定することはできない。

## AJIMEEの1周・3周比較

| 区分 | 件数 | 完全一致率: 1周 → 3周 | 平均MinCER: 1周 → 3周 | 生成上限到達: 1周 → 3周 |
| --- | ---: | ---: | ---: | ---: |
| 全体 | 200 | 1.50% → 5.50% | 0.6848 → 0.5889 | 2 → 1 |
| 文脈あり | 100 | 2.00% → 6.00% | 0.6691 → 0.5514 | 1 → 0 |
| 文脈なし | 100 | 1.00% → 5.00% | 0.7006 → 0.6265 | 1 → 1 |

完全一致は3件から11件へ、4.00ポイント増えた。
前回正解だった3件はすべて維持し、新たに8件が正解になった。
平均MinCERは0.0959低下し、前回に対する相対的な減少は約14.0%だった。
これは文字誤りの指標の変化であり、完全一致率が14ポイント上がったという意味ではない。

同じ問題どうしのMinCERを比較すると、118件で改善、32件で同値、50件で悪化した。
全体では改善したが、すべての問題で良くなったわけではない。
MinCERは低いほど良く、余分な生成が多い場合は1を超える。

## 改善した例と残っている誤り

次の例では、1周時点で別の語句に置き換えていた箇所が、3周で正解になった。

| 読み | 1周の予測 | 3周の予測・許容解 |
| --- | --- | --- |
| シャトルバスガウンコウサレテイタジキ | シャトルバスが運行されていた場合 | シャトルバスが運行されていた時期 |
| スグフクキャプテンニシュウニン | すぐ降格キャプテンに降格 | すぐ副キャプテンに就任 |

この変化から、生成を短くして終了する能力だけでなく、
入力に沿った文字列を生成する能力にも改善があると判断できる。

一方、初回レポートで挙げた「ノイライガクルヨウニ」は改善しなかった。
許容解は「の依頼が来るように」だが、
1周では「の影響が働くように」、3周では「読んでる人が来るように」と出力した。
この項目のMinCERは0.4444から0.5556に悪化し、入力の読みを守れていない。

また、3周でも1件で「ッ」を繰り返し、生成上限に達した。
上限到達件数は減ったものの、反復生成の問題は解消していない。

## 解釈の範囲

今回の200件では、同じ5,000件の学習を1周から3周へ増やす効果を確認できた。
ただし完全一致は5.50%であり、モデル単体の変換精度には改善の余地が大きい。
この結果だけで、さらに周回数を増やせば同じように改善するとは言えない。

文脈あり100件と文脈なし100件は別の問題群である。
6.00%対5.00%という差から、文脈を与える効果は判断できない。
同じ問題で文脈を付け外しする比較は未実施。

辞書・探索・読みの制約を組み合わせたIME全体の精度や、既存IMEとの優劣は未評価。
別のseedでの再現性、GPUのコンピュートユニット消費量も確認していない。

## 次の実験案

同じ5,000件の周回数をさらに増やすことよりも、学習データの種類数を増やす比較を優先する。
学習ログ上は正解トークンを高い割合で予測できるようになった一方、
評価では読みから外れる誤変換が残っているためである。
データの種類が足りないという仮説であり、原因を確定したものではない。

モデル・プロンプト・評価条件を揃え、データ件数・周回数・総更新数を記録する。
データを増やすと計算量も変わるため、改善をデータの多様性だけに帰属させない。
完全一致率・平均MinCER・生成上限到達件数と、同じ問題の改善・悪化を比較する。

データを増やした学習は未実施であり、その効果はまだ確認していない。
