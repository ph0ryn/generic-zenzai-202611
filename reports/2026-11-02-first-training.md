# LLM-jp-150M 初回学習とAJIMEE評価

実施日: 2026年11月2日

5,000件・1周の追加学習で、生成が止まらない状態から、
多くの入力で変換結果らしい文字列を出して終了する状態へ改善した。
ただし完全一致は200件中3件で、読みを正確に変換する能力はまだ不十分だった。

## 実験条件

| 項目 | 条件 |
| --- | --- |
| モデル | LLM-jp-3-150m |
| 学習方式 | 全パラメータの追加学習 |
| 学習データ | 5,000件。Wikipedia由来2,196件、LLM-jpコーパス由来2,804件 |
| 入力 | 直前40文字までの文脈と、カタカナの読み |
| 学習対象 | 正解の変換結果と終了記号。入力部分には損失を付けない |
| 周回数 | 1 epoch、157更新 |
| バッチ | 2件 × 勾配累積16回。実効32件 |
| 学習率 | 5e-5。最初の5%で増やし、その後は線形に減衰 |
| 長さ上限 | 入力と正解を合わせて512トークン |
| 実行環境 | Google Colab / CUDA、fp16混合精度 |
| 評価 | AJIMEEの200件。文脈あり・なし各100件 |
| 生成条件 | fp32、greedy、生成上限128トークン |

出典別の件数は、初期データを同梱したcommit `41db856`の出典記録に基づく。

学習前のモデルと学習済みモデルを、同じ200件で比較した。
保存された評価記録から、入力・文脈・許容解・プロンプト・生成条件の一致を確認し、
予測200件ずつを再採点して集計結果と一致することを確認した。

## 学習の実行結果

学習とモデルの保存は完了した。
記録された学習時間は363.0秒、約6分3秒。
これは学習処理の時間であり、環境構築やモデル取得の時間ではない。
学習全体の平均lossは2.8823、完了時のログのトークン正解率は60.09%だった。

学習中のトークン正解率は、正解文のそれまでの部分を与えて、
次のトークンを当てる指標である。
評価時に文章全体を自力で生成する完全一致率とは異なる。

実行準備中には、bf16のエミュレーション対応をハードウェア対応として扱う判定により、
T4で実行できない計算を選んで停止した。
ハードウェア対応だけで判定するよう修正し、fp16で学習が完走した。

## AJIMEEの学習前後比較

| 区分 | 件数 | 完全一致率: 前 → 後 | 平均MinCER: 前 → 後 | 生成上限到達: 前 → 後 |
| --- | ---: | ---: | ---: | ---: |
| 全体 | 200 | 0.00% → 1.50% | 13.3968 → 0.6848 | 200 → 2 |
| 文脈あり | 100 | 0.00% → 2.00% | 14.0053 → 0.6691 | 100 → 1 |
| 文脈なし | 100 | 0.00% → 1.00% | 12.7884 → 0.7006 | 100 → 1 |

完全一致は0件から3件に増えた。
同じ項目どうしのMinCER比較では、199件で改善、1件で悪化した。

MinCERは、複数の許容解のうち最も小さい「文字編集距離 ÷ 正解の文字数」であり、
低いほど良い。余分な文字を大量に生成すると1を超える。
表の平均は、項目ごとのMinCERを単純平均した値である。

学習前は記号・空白・同じ文の反復が多く、全200件で上限の128トークンまで生成した。
学習後は198件で終了記号を出して停止し、平均生成トークン数は14.65になった。
したがってMinCERの大きな改善には、生成を止められるようになった効果が含まれる。
文字変換そのものの精度が同じ割合で改善した、という意味ではない。

## 残っている誤り

入力と同じ読みになる文字列を選べず、別の語句に置き換える例が見られた。

| 読み | 許容解 | 学習後の予測 |
| --- | --- | --- |
| ノイライガクルヨウニ | の依頼が来るように | の影響が働くように |
| クケイジョウニハイレツシタ | 矩形状に配列した | 傾向に追いついた |

補助的な確認でも、表示形式だけでは説明できない誤りが残った。

- 空白除去とUnicode NFKC正規化を予測・許容解の両方に適用しても、
  完全一致は3件のままだった。表の正式な評価値には、この正規化を適用していない。
- 生成上限に達した2件を除く198件でも、平均MinCERは0.6538だった。
- 学習データ5,000件の正解文字列と評価の許容解に、完全一致する重複はなかった。
  同一文書に由来する例や部分一致までは調べていない。

今回確認できたのは、追加学習によってタスクへの適応が進んだことと、
それでも入力の読みへの忠実さが足りないことである。
学習量の不足が原因なのか、データの内容やモデルの能力が主な制約なのかは、
この実験だけでは確定できない。

## 解釈の範囲

文脈あり100件と文脈なし100件は別の問題群である。
2.00%対1.00%という差から、文脈を与える効果があったとは判断できない。
その確認には、同じ問題で文脈を付け外しする比較が必要になる。

今回の結果はモデル単体の自由生成による評価である。
辞書・探索・読みの制約を組み合わせたIME全体の精度や、既存IMEとの優劣は未評価。
単一の学習runと200件の結果であり、モデルサイズの限界や最適な周回数も判断していない。
GPUのコンピュートユニット消費量は未計測。

## 次の実験案

学習前の同じモデルから、同じ5,000件を3周学習する。
周回数以外の設定と評価条件を揃え、今回の1周学習と比較する。
完了済みモデルにさらに3周を追加する実験ではない。

確認したいのは、学習量を増やすことで読みと表記の対応が改善するかである。
学習lossだけで判断せず、完全一致率・平均MinCER・生成上限到達件数に加えて、
読みから外れる出力が減ったかを確認する。
改善しなければ、周回数を増やし続ける前にデータ内容や読みの制約を再検討する。

この3周学習は未実施であり、改善を保証するものではない。
