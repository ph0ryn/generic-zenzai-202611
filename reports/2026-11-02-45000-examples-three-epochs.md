# LLM-jp-150M 45,000件の3周学習とAJIMEE評価

実施日: 2026年11月2日

[45,000件の1周学習](2026-11-02-45000-examples.md)に続き、3周学習した結果を比較した。
完全一致は200件中38件から56件へ増え、平均MinCERは0.2372から0.1925に下がった。
平均MinCERの相対的な減少は約18.8%で、生成上限到達・空出力はともに0件を維持した。

今回はバッチ構成も2件×勾配累積16回から32件×累積1回へ変更されている。
実効バッチは32件のままだが、周回数だけを変えた比較ではない。
更新数は3倍になった一方、学習時間は約50分37秒から約44分28秒へ短縮した。

本レポートは共有された実験サマリーと前回のレポートに基づく。
Driveの個別予測の確認や再採点は行っていない。

## 実験条件

| 項目 | 条件 |
| --- | --- |
| 元モデル | LLM-jp-3-150m |
| 学習データ・周回数 | 45,000件、3 epochs |
| 入力 | 直前40文字までの文脈と、カタカナの読み |
| バッチ | 32件 × 勾配累積1回。実効32件 |
| 学習率・seed | 5e-5、seed 42 |
| 学習時の長さ上限・精度 | 入力と正解を合わせて512トークン、fp16 |
| 評価 | AJIMEEの200件。文脈あり・なし各100件 |
| 生成条件 | fp32、greedy、生成上限64トークン |
| 評価時の長さ上限 | 入力と生成を合わせて512トークン |
| 実行環境 | Google Colab / CUDA、PyTorch 2.14.1+cu126、Transformers 5.22.1 |

サマリー上では、前回と元モデル・データ件数・学習率・seed・評価条件が一致する。
3周は合計の周回数であり、1周学習済みモデルにさらに3周を追加する実験ではない。
データの内容やモデルの同一性を、保存ファイルどうしで照合したものではない。
採点は許容解との完全一致とMinCERで、空白除去や表記の正規化は行わない。

## 学習量・時間・学習指標の比較

| 指標 | 1周 | 3周 |
| --- | ---: | ---: |
| 延べ学習件数 | 45,000件 | 135,000件 |
| バッチ件数 × 勾配累積回数 | 2 × 16 | 32 × 1 |
| 実効バッチ | 32件 | 32件 |
| 更新回数 | 1,407 | 4,221 |
| 学習時間 | 3,036.8秒（約50分37秒） | 2,667.8秒（約44分28秒） |
| 1秒あたりの更新回数 | 約0.463 | 約1.582 |
| 学習loss | 1.6343 | 0.7983 |
| 最終ログ区間のトークン正解率 | 81.48% | 95.65% |

学習時間は369.0秒、約6分9秒短くなり、前回に対して約12.2%減少した。
更新回数と学習時間から計算した1秒あたりの更新回数は、約3.41倍になった。
時間は学習処理の記録値であり、環境構築・モデル取得・評価の時間を含めない。

一度に処理する件数を増やし、勾配累積の回数を減らした変更は高速化と整合する。
ただしサマリーにはGPU機種や利用状況がなく、同じ周回数での比較もないため、
速度差のすべてをバッチ構成の変更だけに帰属させることはできない。
前回の速度に基づく「3周で約2時間32分」という見積もりは、今回の条件には当てはまらなかった。

学習lossは下がり、最終ログ区間のトークン正解率も上がった。
この正解率は、正解文のそれまでの部分を与えて次のトークンを当てる指標であり、
文章全体を自力で生成する評価時の完全一致率とは異なる。
95.65%とAJIMEEの28.00%を直接比較して、過学習や変換能力の限界とは判断できない。

## AJIMEEの1周・3周比較

| 区分 | 件数 | 完全一致: 1周 → 3周 | 平均MinCER: 1周 → 3周 |
| --- | ---: | ---: | ---: |
| 全体 | 200 | 19.00%（38件） → 28.00%（56件） | 0.2372 → 0.1925 |
| 文脈あり | 100 | 17.00%（17件） → 29.00%（29件） | 0.2268 → 0.1880 |
| 文脈なし | 100 | 21.00%（21件） → 27.00%（27件） | 0.2477 → 0.1970 |

完全一致率は9.00ポイント上昇し、正解数は差し引き18件増えた。
文脈ありでは12件、文脈なしでは6件増えている。
個別予測を比較していないため、前回の正解を何件維持したか、
新たに正解になった項目が何件あるかは分からない。

平均MinCERは0.0447下がり、1周に対して約18.8%減少した。
文脈ありでは約17.1%、文脈なしでは約20.5%減少している。
両方の問題群で、完全一致率と平均MinCERが改善した。

| 生成に関する指標 | 1周 | 3周 |
| --- | ---: | ---: |
| 生成上限到達 | 0件 | 0件 |
| 空出力 | 0件 | 0件 |
| 平均生成トークン数 | 13.19 | 13.07 |

生成トークン数には終了記号を含む。
両方とも全200件が終了記号を出して停止しており、
今回の差は生成上限到達や空出力の件数が減ったことによるものではない。

## 解釈の範囲

今回の設定変更を含む3周学習は、1周学習より良い変換成績を示した。
ただし、実効バッチが同じでもバッチ構成を同時に変更しているため、
改善幅を周回数だけの効果とは扱わない。
周回数に伴い、学習率の減衰に使う更新回数も増えている。

文脈あり100件と文脈なし100件は別の問題群である。
文脈ありの完全一致率が29.00%で、文脈なしの27.00%を上回ったことだけでは、
文脈が有効に使われたことや文脈理解が向上したことは判断できない。

完全一致は56件で、残る144件は許容解と一致していない。
個別問題の改善・悪化、誤変換の種類、学習データと評価データの重複、別seedでの再現性は未確認。
最適な周回数や他モデルに対する優位性、IME全体の精度も、この比較だけでは判断できない。

## 次の実験案

元モデルから135,000件を1周学習する比較を候補とする。
内訳はWikipedia由来67,500件、LLM-jpコーパス由来67,500件とし、今回と延べ学習件数を揃える。
1:1は出典ごとの暫定的な配分であり、この比率が優れていることは未検証。
バッチ32件・勾配累積1回と評価条件を維持し、
45,000件を3回学習する場合と、より多くの例を1回ずつ学習する場合を比べる。

元データの先頭範囲を現行コードで抽出し、各出典から67,500件を確保できることを確認した。
その135,000件の内訳は文脈あり43,420件・なし91,580件で、文脈の有無は半々ではない。
データの長さや内容も変わるため、実際の更新回数・学習時間と評価成績を合わせて確認する。
この135,000件の学習・評価結果は、まだ得られていない。
